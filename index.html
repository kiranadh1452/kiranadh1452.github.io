[01] About

For two years I was the Lead Full-Stack Engineer at 2sync, a SaaS that keeps Notion in two-way sync with Google, Microsoft, and Todoist. Its code writes directly into customers’ calendars, contacts, and inboxes, so a bug costs someone real data. I built seven of its ten integrations, the guardrails that stop a flaky API from deleting customer data, and the release process that let me run production alone for a month.

I learned architecture the slow way, before coding agents. Now I use Claude Code every day. I write the specs and skills the agent works from, I decide the design, and I test its output against real data before anything ships. The agent makes me faster—it doesn’t make my decisions.

I’m looking for one or two teams that want a senior engineer who can own a product end-to-end. 02

Fault-Tolerant Queue Orchestration & Deletion-Safety Guardrails

Context
In multi-provider sync engines, stalled workers can hang silently while partial third-party API responses can trick diff engines into wiping user records.
Approach
Designed a step-level Redis heartbeat system tied to execution IDs to detect and terminate stalled jobs, multi-stage upstream verification before any deletion, and a capped two-stage daily health monitor across customer automations.
Outcome
Eliminated false-deletion failure modes, ran zero-downtime MongoDB migrations with rollback scripts, and maintained production data integrity across 7 of 2sync’s 10 integrations.
Redis Job queues MongoDB
